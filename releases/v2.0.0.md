# Frank Yomik v2.0.0

Version 2 rebuilds the processing pipeline around explicit, verified stages
while preserving Frank Yomik's focused reading experience: Kindle manga,
Japanese prose furigana, and Naver Webtoon through the lens or full-page view.

## Quality and reliability

- Rich semantic detection records balloons, dialogue, artwork text, SFX,
  masks, relationships, and reading order while retaining the proven RT-DETR
  production model.
- Japanese OCR has a deterministic routing and validation contract. Manga OCR
  remains the shipped engine; the stronger Hayai benchmark candidate stays
  disabled until its training-data provenance permits distribution.
- Translation is page batched with stable region IDs, bounded structured
  responses, reading context, and target-language cache separation.
- Cleanup selects safe fills or supervised LaMa, changes pixels only inside
  verified masks, and retains the exact cleanup base for rerendering.
- Manga and webtoon rendering consumes PageDocument metadata and records actual
  font size, line count, fit, overflow, and ellipsis outcomes.
- Atomic submission deduplication, worker capability heartbeats, revision
  matching, and abandoned-job recovery harden two-worker production operation.

## Storage and compatibility

Public pipeline names and v1 job, status, and image endpoints remain stable.
Version 2 writes cache manifest schema 4 and PageDocument schema 2. Cache
identity includes the complete pipeline revision and target language. Existing
legacy results are preserved but do not silently satisfy a v2 request.

See [Version 2 compatibility](../docs/compatibility_v2.md) for client/server
pairing and schema behavior.

## Upgrade

1. Back up Redis and the cache directory.
2. Preserve the v1 API and worker digest references for the rollback window.
3. Pull or build the v2 API and worker as a matched pair.
4. Confirm the pinned `qwen3:14b` Ollama digest and persistent model caches.
5. Deploy with `bin/deploy v2.0.0 rocm` or follow the generic CPU Compose path.
6. Require `/api/v1/health` to show ready workers at the API's exact pipeline
   revision before submitting pages.

The ROCm production deployment requires access to `/dev/kfd` and `/dev/dri`
and the host render/video group IDs. The generic worker runs on CPU. Model
identities, caches, and hardware expectations are in
[Model inventory](../docs/models.md).

## Rollback

Stop v2 writers, clone the cache to an isolated rollback directory, and start
the preserved v1 image pair through `docker-compose.v1-rollback.yml`. Never
point v1 at the live v2 cache. The release rehearsal verified this path and
restored v2 without changing the live cache inventory. Exact commands are in
[Deployment](../docs/deployment.md).

## Known limitations

- Hayai OCR and FLUX.2 Klein are benchmarked candidates and are disabled in the
  release. Their quality gains are documented, but their production provenance
  or routing gates are incomplete.
- A webtoon cleanup that falls back after a LaMa failure is returned to the
  requesting job with degraded provenance and is not stored as a durable cache
  hit.
- Version 2 remains a trusted single-tenant self-hosted service.
