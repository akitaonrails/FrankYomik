# v0.6.0

## Japanese text books

Kindle renders reflowable novels the same way it renders manga — one image per
page, no text in the DOM — so a book could not be annotated by injecting ruby,
and it used to reach the manga pipeline, where bubble detection finds nothing.

The new `book_furigana` pipeline treats the page as what it is: typeset prose.
Columns are found by their own regularity, read in short slices (manga-ocr
returns gibberish for a whole column and is exact for a dozen glyphs), and the
readings are drawn into the gutters where vertical Japanese puts ruby anyway.
Nothing on the page itself is redrawn, and gutters that already hold the
publisher's own ruby are left alone.

Pick it per volume: the app's toolbar cycles Furigana → English → Book, and the
extension popup has **Pipeline for this book** under Current page. Each volume
remembers its own choice, so moving between a novel and a manga needs no
setting changes. A page sent to the wrong pipeline is refused with an
explanation rather than annotated as if it were a novel.

## Peeking that does not disturb the reader

The magnifier introduced in v0.5.0 shared the page with Kindle's own gestures.
It no longer does:

- Moving the pointer with the lens open dragged the page sideways underneath
  it. A held peek now takes those events away from the reader entirely.
- Releasing a peek popped Kindle's highlight/copy/note menu, because its
  long-press selection had already started. Opening the lens now cancels that
  gesture and clears the selection.
- Holding on a page whose translation had not arrived did nothing and then
  turned the page, so waiting cost you your place. The hold is absorbed
  instead, and if the render lands while you are still holding, the lens
  opens under your pointer.

Quick taps are untouched throughout: page turns and webtoon scrolling behave
exactly as before.

## Stops and diagnostics

- A page that fails for a reason it cannot change — the wrong pipeline for the
  book — used to be resubmitted every twenty seconds for as long as the tab
  stayed open, because Kindle regenerates its blob URLs. Three identical
  failures now pause auto-submission and report the server's own message.
- Settings changed in the extension popup reach an open reader immediately.
  They used to need a tab reload.
- The "no visible blob page image" notice now comes only from the frame that
  actually hosts the reader.

## Fixes found while testing this release

- A peek stopped tracking the pointer the moment it opened. The cancel sent
  to abort Kindle's own selection was arriving back at our own handler first,
  which ended the hold while the magnifier went on to appear — visible, frozen,
  and no longer keeping the page still underneath.
- A reader could go quiet for good. Detection pauses while the page is
  painting, and the loader it watches for is matched by any class containing
  "loader"; anything matching that never went away disabled the reader for the
  life of the page, silently. The gate is now believed for five seconds.
- `FrankKindle.state()` and `FrankLens.state()` report why nothing is
  happening — configuration, frame, loader, page image, registrations — from
  the extension's console context.

## Memory and dependencies

- Page retention is bounded by bytes as well as page count, since a prose
  render is much larger than a manga one; the page in front of you is always
  kept.
- Server dependencies stop at their majors. The file was unpinned, and a
  routine CVE rebuild had silently moved opencv from 4 to 5 in production.
